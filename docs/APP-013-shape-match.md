# APP-013 かたちポン！ 仕様・設計

更新日：2026-10-08
状態：5動物・図形サイズ・アニメーション調整仕様確定／Codex改修待ち

## 2026-10-08 採用済みデザイン・5動物改修仕様（現行優先）

PMによる確認結果：
- 既存の「1画面1図形→動物完成→固有動作→次の動物」という体験と動きの方向性は採用。
- 参考イラストの絵本風・柔らかい・丸みのあるデザインも採用。ただし参考画像の動物・図形の割当を自動的に仕様化しない。
- 現在の課題は、図形と動物のサイズ・輪郭が噛み合わないこと、動作のぎこちなさ。3動物から5動物へ増やす。

### 5ステージ（正式採用順）

1. **○ かめ**：丸い甲羅を大きな欠けパーツとする。甲羅の縁と胴体・頭・足が自然につながる。完成後は頭を優しく動かす。
2. **横長長方形 いぬ**：胴体を幅広の丸角長方形とし、正方形にはしない。脚・首・しっぽとの接続位置を自然にする。完成後はしっぽを優しく振る。
3. **たまご形（縦長だ円） ひよこ**：卵のような縦長の胴体をはめる。顔・羽・足を組み合わせ、完成後に小さく一度だけ弾む。
4. **△ きつね**：丸みを帯びた三角の顔を完成パーツとする。顔、耳、頬、胴体、しっぽを一体の絵本風シルエットとして自然につなぎ、ぎこちない鋭角やパーツの浮きをなくす。完成後は耳を控えめに動かす。
5. **◇ さかな**：角を少し丸めたひし形の胴体をはめる。尾びれ・背びれ・目と自然につながり、完成後はしっぽを振りながら短くゆっくり泳ぐ。

固定循環：かめ→いぬ→ひよこ→きつね→さかな→かめ。ねこは採用しない。

### 図形と動物を一致させる設計

- 図形の輪郭と欠けた部分の輪郭を同一SVG pathデータ／同一形状定義に基づき作ること。図形と穴の幅・高さ・縦横比・角丸を対応させる。
- 正方形の共通サイズをそのまま全動物へ強制しない。見た目の胴体・顔に合わせ、図形ごとの縦横比、配置、実寸を設定する。
- 動物全体のデザインを優先しつつ、幼児にとって図形がつかみやすい大きさを維持する。横長長方形も縦長卵形も最低限の大きなタッチ領域を確保する。
- はまった瞬間に図形だけが消えて穴が着色されるような不自然な切替を避け、同じパーツがその場で完成したように見せる。
- 完成前の動物周辺パーツは薄く残し、完成後に絵本の絵として一体化する。顔・耳・足・しっぽのパーツ間の隙間、不自然な重なり、浮き、切れを目視検証する。

### 滑らかな動き

- ドラッグの追従→吸着→完成→動物アニメーション→フェード→次ステージを滑らかにつなぐ。特に吸着開始と終了で突然位置・サイズ・向きが飛ばないこと。
- 吸着時は短いease-out等、動物の動きは穏やかなease-in-out。移動や回転の支点は頭・耳・しっぽ等の付け根に合わせる。
- 同時に派手な複数演出を起こさず、ステージごとに短い固有動作を1回だけ再生する。
- 完成を認識できる保持時間を維持し、次の動物へ自動進行。既存のタイムライン（スナップ180ms、完成保持1400ms、フェード220ms）を起点に、実際に滑らかに感じる範囲で小幅調整可能。
- prefers-reduced-motionで大きな動きを止めても、完成・次ステージは明確に分かるようにする。

### 維持条件・検証

1画面1図形1動物、広い自動吸着、誤配置ペナルティなし、無音、保存なし、外部通信なし、非公開試作の状態を維持する。Pointer Events、複数指、連打、BFCache、中断、回転、safe area、100dvh、reduced-motion、タイマー／DOM増殖防止、既存公開アプリ回帰は必須。

最低検証：5動物すべてで欠けた形とピースの縦横比一致／完成の自然さ／アニメーション／固定循環、390×844・844×390・1024×768、連続2〜3分。正式公開、ポータル、共通ホーム、GA4、Clarity、ConoHa allowlistはiPhone実機のPM確認後に別判断。

## 目的

1歳半〜2歳前後を主対象としつつ、1歳児でも遊びやすい難易度へ下げたドラッグ型Webアプリとする。

「図形を持つ → 大きな型へ近づける → 図形がはまる → 動物が完成して動く → 次の図形へ進む」という単純な因果を、説明なしで楽しめることを最優先とする。

知識テストや正誤評価を主目的にせず、形の違い、指で運ぶ動作、完成時のご褒美反応を楽しむ。

## 対象

- 主対象：1歳6か月〜2歳前後
- 1歳児でも成功しやすい操作難易度を優先する
- 精密なドラッグや正確な指離しを要求しない

## 1画面1図形

- 旧MVPの「3図形＋3型を同時表示」は廃止する
- 1画面には大きな図形ピース1個と、対応する大きな動物型1個だけを表示する
- 選択・探索の負荷を減らし、「今これを運ぶ」が一目で分かる構成にする
- 図形は旧版より約1.3〜1.5倍を目安に大きくする
- スマートフォン縦では概ね120〜150px程度を基準とし、短辺に応じてレスポンシブ調整する

## 基本操作

- 画面下側の大きな図形ピースをドラッグする
- 画面中央〜上側の大きな動物型へ近づける
- 図形中心が十分広い吸着範囲へ入ったら、pointerupを待たず自動で吸い込まれるようにスナップしてよい
- 正確な位置合わせや「型の上で指を離す」操作は要求しない
- 吸着範囲外で指を離した場合は、否定表現なしでピースが元位置へやさしく戻る
- スコア、回数、制限時間、ランキングは表示しない

## 図形と動物

図形そのものが動物を完成させる大きなパーツになる。

初期3種は以下を第一候補とする。

- ○：かめ
  - 円が甲羅になる
  - 甲羅の周囲に頭・足・しっぽを薄く見せ、円が入ると「かめ」が完成する
  - 完成後は頭や足を少し動かす／1〜2歩程度の穏やかな動き
- □：いぬ
  - 角を丸めた四角が胴体になる
  - 頭・足・しっぽが周囲にあり、四角が入ると「いぬ」が完成する
  - 完成後はしっぽを振る／小さく1回弾む
- △：きつね
  - 三角が顔または大きな中心パーツになる
  - 耳・体など周囲のパーツとつながって「きつね」が完成する
  - 完成後は耳を少し動かす／小さくぴょんと動く

動物はリアルさより、図形との対応が一目で分かる単純な「図形どうぶつ」表現を優先する。

実装時に□いぬ、△きつねの見た目が不自然な場合は、同じ図形対応を保ったまま別の親しみやすい動物へ差し替えてよい。ただし大きな判断はPM確認を優先する。

## 型の見せ方

- 動物は完成前から全体を強く見せすぎず、周囲の頭・足・耳などを薄めに見せる
- 中央の欠けた図形部分を大きな型として分かりやすく見せる
- 「図形を入れると動物が完成する」構造が視覚的に理解できることを優先する
- 型に近づいた時は、ごく控えめに明るくする／少し大きくするなど吸着予告を出してよい
- 赤色、×、警告、強い揺れ等の否定表現は使用しない

## 正解時の流れ

1. 図形が広い吸着範囲へ入る
2. 図形が自動で型中央へ短くスナップする
3. 動物全体の色・輪郭が完成する
4. その動物固有の短いアニメーションを1回だけ行う
5. 約1.2〜1.8秒程度で演出を終える
6. 動物が穏やかに画面外へ移動またはフェードする
7. 次の図形＋次の動物へ自動で切り替える

基本順は ○かめ → □いぬ → △きつね → ○かめ… の固定循環から開始する。

MVPではランダム化や難易度上昇は行わない。

## 動物アニメーション

- 各動物の反応は1つに限定する
- 1回だけの小さな動きとする
- 全画面を横切る高速移動や連続ジャンプは行わない
- 画面揺れ、強い点滅、突然の拡大は使用しない
- 動物が完成した喜びが分かる程度の低刺激な演出とする

## 誤配置時

- 不正解表示をしない
- 吸着範囲外で離した場合は200〜350ms程度で元位置へ戻す
- 赤色、×、減点、ブザー、強い振動は使用しない
- 戻った直後からすぐ再操作できる

## 入力

- Pointer Eventsを使用する
- 操作対象は1ピースのみ
- 最初のpointerIdだけがピースを操作する
- 他の指が同時に触れても状態を増やさず、遊びを破綻させない
- pointerup、pointercancel、lostpointercaptureで所有権を確実に解放する
- 完成演出中は追加入力で演出・タイマーを重複開始しない

## reduced-motion

- 図形のスナップと完成状態は維持する
- 動物の歩行、跳ね、しっぽ、耳などの反復・大きな動きを停止または大幅に縮小する
- 次の動物への切替はフェード等の小さな変化にする
- reduced-motionでも「はまった → 動物が完成 → 次へ」が理解できること

## 音

- 改修MVPも音なしで成立させる
- 動物の鳴き声や「ぽん」効果音は実機確認後の追加候補とする
- 音がなくても完成と次への進行が理解できることを完了条件とする

## 技術設計

- HTML / CSS / Vanilla JavaScript
- 外部ライブラリなし
- 旧APP-013のPointer Events、safe area、100dvh、中断復帰、BFCache等の安全処理を再利用する
- 3ピース／3target同時管理は廃止し、currentStage 1件を中心とした単純な状態管理へ変更する
- ステージデータとして shape / animal / animation type / visual data を固定配列で持ってよい
- SVGまたは固定DOM/CSSで図形どうぶつを表現し、操作ごとにDOMを増やさない
- 完成演出・次ステージ切替のタイマーは管理対象を限定し、重複させない
- 画面回転・resize後は現在の図形と型を安全な位置へ再計算する

## 中断・復帰

- visibilitychange / pagehideでactive pointerと完成演出用タイマーを解除する
- 復帰時は二重タイマー・二重イベントを作らない
- BFCache復帰後も現在のステージが安定して操作可能であること
- 中断タイミングによって動物が半端な完成状態で残らないこと
