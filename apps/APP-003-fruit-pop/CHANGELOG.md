# APP-003 変更履歴

## 2026-08-24 — iPhone Safari音声不具合の修正

### 実機結果と原因候補

- iPhone Safari／GitHub Pagesで、音声ONでも果物名が出ず実機FAIL
- 正式MP3未配置にもかかわらず、MP3の非同期失敗後にWeb Speech APIを呼んでいた
- 読み上げ開始がタップ操作から離れ、Safariの音声許可条件を満たしにくい構造だった
- 720ms後の自動切り替えでも読み上げをキャンセルしていた

### 修正

- MVPでは存在しないMP3へアクセスせず、タップ処理内からWeb Speech APIを直接呼ぶ
- 720msの自動切り替えでは読み上げを強制停止せず、語尾が切れにくいようにする
- 再タップ時は直前の読み上げをキャンセルして即時再開始し、大量に重ねない
- 音OFF、ページ非表示、途中退出では読み上げを停止する
- 将来正式MP3を配置したときだけ`useOfficialAudio`を有効化できる構造を維持する

### Codex回帰テスト

- 模擬Web Speech APIで、果物タップ直後に「りんご！」が1回呼ばれることを確認
- 720ms後にバナナへ切り替わっても読み上げキャンセルが追加されないことを確認
- 5回高速タップ時は各タップ前に直前の読み上げを停止して再開始し、音声をキューへ積み重ねないことを確認
- 音OFF中の果物タップでは読み上げ回数が増えないことを確認
- 音ONへ戻した次の果物タップで読み上げが再開することを確認
- 途中退出・履歴復帰後に演出・粒子が残らないことを確認
- ローカルサーバーのアクセス記録にMP3リクエストが発生しないことを確認
- JavaScript構文、差分形式を確認
- GitHub Pagesで直接読み上げ分岐、MP3無効、自動切り替え時の音声維持を含む最新JavaScriptの配信を確認
- 公開URLで果物演出、自動循環、スクロールなし、コンソールエラー・警告なしを確認

### 実機判定

- 音声以外：果物自動循環、高速連打、2本指、縦横回転、safe areaはPASS
- 音声：コード経路／Pages反映PASS、修正版のiPhone実音声は再確認待ち
- APP-003正式公開判定：保留

## 2026-08-24 — 果物タップだけで進む操作へ変更

### PM確定仕様

- 子ども画面から「まえ」「つぎ」ボタンとページ表示を削除
- 中央の果物をタップすると、直後に固有演出・名前・音声を返す
- 演出後、りんご→バナナ→いちご→ぶどうの順で1つだけ自動的に進む
- 再タップ・複数指・高速タップ時は同じ果物の演出を再開始し、最後の入力から1回だけ進む

### 維持した実装

- 正式画像・MP3未配置時の絵文字・Web Speech APIフォールバック
- 音声ON/OFFと音OFF設定保存
- 中断、復帰、BFCache、古い音声・タイマー・装飾DOMの後片付け
- safe area、`100dvh`、`prefers-reduced-motion`、キーボード、ARIA
- 子ども画面に回数・スコア・ランキングを表示しない方針

### Codex回帰テスト

- りんご→バナナ→いちご→ぶどう→りんごの順序を確認
- タップ直後に固有演出、名前、通常8粒が表示されることを確認
- 10回高速タップ中は同じ果物・粒子8個・名前表示1個を維持し、最後の入力から約720ms後に1つだけ進むことを確認
- 演出終了、切り替え、途中退出・履歴復帰後に粒子・名前表示・古いクラスが残らないことを確認
- 音OFFでも循環し、再読み込み・履歴復帰後も音OFFを維持することを確認
- Enterキーでタップと同じ演出・自動循環になることを確認
- 390×844、844×390、1024×768で縦横スクロールなし
- 子ども画面のボタンが果物と音声の2個だけであることを確認
- JavaScript構文、差分形式、ブラウザコンソールエラー・警告なし
- GitHub Pagesでナビゲーション削除、タップ直後の8粒、約720ms後のバナナ切り替え、音OFF再読み込み保持、390×844のスクロールなし、コンソールエラー・警告なしを確認

### 実機確認待ち

- iPhone／Android実機の実際の2本指、高速タップ、音量・音質
- safe area、画面回転、バックグラウンド・BFCache復帰
- `prefers-reduced-motion: reduce`有効時の刺激と操作感
- 幼児本人にとって約720msの切り替えタイミングが適切か
- 1〜2分利用時の発熱・動作低下
